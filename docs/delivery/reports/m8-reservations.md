P9 and P10 implement request and confirmation for `BOOKING` and `GUEST_SESSION`. Codes last ten minutes and allow five attempts. The code is an identity-bound HMAC-SHA-256 under `PHONE_VERIFICATION_SECRET`; tokens are 256-bit random values stored only as SHA-256, valid for thirty minutes. A phone-scoped PostgreSQL advisory lock serializes request admission even without a guest row. Confirmation locks the guest first, then the verification row. Invalid guesses commit their attempt count before the public error is returned. Unknown, expired, exhausted and already-confirmed verifications return 410. Resends leave prior codes valid until their own expiry and add no separate cooldown.

Limits are three requests per phone per rolling fifteen minutes and ten per rolling twenty-four hours, shared across purposes; client buckets allow ten requests per hour and twenty confirmations per ten minutes. Both namespaces participate in the existing bounded cleanup. Missing trusted client addresses share an anonymous bucket. Filled honeypots within the body cap get the same generic 422. Guest and verification lock timeouts use the same public detail.

## Summary

The fake checkout sends signed HTTP callbacks to the configured application origin, and its production gate runs before it reads checkout state. The implementation follows the approved event shape. Reviewing it against the planned refund consumer exposed a missing identity that affects retries.

## Major

### 🟠 Refund callbacks cannot identify the attempt they complete, `src/application/payments/ports.ts:36`

**Problem.** Each attempt has its own idempotency key and the fake generates a provider refund ID. Its terminal event carries only the original payment and transaction IDs, money, and an opaque event ID. Consider an attempt that returns FAILED synchronously. Staff retry, and the second attempt returns PENDING. The first attempt's failure notification then arrives for the first time. A consumer following Decisions 5 and 7 sees a new event matching every payment field and a pending refund.

**Impact.** The old event can mark the active retry failed. If that retry succeeds, its callback finds the payment outside REFUND_PENDING. The guest can have their money back while the system keeps the reservation confirmed.

**Suggested fix.** Ask the owner to resolve the Decision 1 contract gap. One option is to require the merchant refund attempt key on normalized refund events and verify it against the active attempt. Another is to treat callbacks as a prompt to query the authoritative outcome by the active attempt key. Cover the delayed first failure followed by second-attempt success in the shared suite and in the future consumer tests.

## Minor

### 🟡 Signed malformed callback coverage, `src/infrastructure/payments/fake/callback.ts:61`

**Problem.** The negative tests exercise missing signatures and signed bytes changed after signing. Neither reaches the decoder or strict schema with an authentic malformed payload.

**Impact.** A change that throws on malformed JSON or forwards an unknown event shape could pass all current signature tests.

**Suggested fix.** Add fake-specific fixtures signed with the test secret for invalid UTF-8, malformed JSON and an unsupported kind/outcome combination. Check for the generic rejection on each.

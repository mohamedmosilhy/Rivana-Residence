# Review, m8-reservations (M8-T3b airport transfer car count), 2026-11-17

**Reviewed by**: Sonnet 5.5 (author on a split of two models)
**Scope**: 30 tracked files plus 4 untracked, uncommitted
**Verdict**: Approve with nits

## Summary
The change adds `PER_VEHICLE`, `ServiceOffering.maxVehicles`, and `ReservationService.vehicles` across migrations, domain, contracts, repositories, and tests. Behavior matches the approved plan: default 1 car, per-branch maximum (default 3, 1 to 10), PER_VEHICLE multiplies and takes no child price, other units record the count, breakfast refuses it, bare kinds still work, field-level 422s, and a fail-closed path when a transfer has no maximum. No blockers or majors. `npx tsc --noEmit` is clean and `tests/unit/domain` passes on my run; I did not rerun the integration suite.

## Minor
### 🟡 Empty details string is kept as "" instead of null, `src/domain/services/service-offering.ts:275`
**Problem**: `details` is trimmed then only length checked, so `"   "` becomes `""` and `value.details ?? null` keeps `""`.
**Why it matters**: T7 will persist this to a nullable column, so "no details" has two representations.
**Suggested fix**: Normalize an empty trimmed value to null in `selectRequestedServices`, and test it.

### 🟡 S36 full replacement silently resets a custom maximum, `src/domain/services/service-offering.ts:119`
**Problem**: Omitting or sending null `maxVehicles` for a transfer stores 3. A client that edits only the price silently overwrites a branch's 7 with 3.
**Why it matters**: Consistent with S36 replacement semantics and audited (the snapshot now includes `maxVehicles`), but it is an easy staff-facing footgun and lowers the cap for later quotes.
**Suggested fix**: Keep the behavior if the owner approved it, but state it explicitly in the S36 contract description and OpenAPI text, and make the staff screen (later task) always send the current value.

### 🟡 Contract and domain `details` rules differ, `src/contracts/api/v1/quotes.ts:49`
**Problem**: The domain schema rejects control and format characters (`service-offering.ts:173-181`); the contract schema only trims and caps at 300. The car-count validator is also duplicated in both files.
**Why it matters**: The route parses with the contract first, then the domain, so behavior is still correct (a 422 from the domain), but OpenAPI over-promises what is accepted and the two copies can drift.
**Suggested fix**: Mention the plain-text rule in the contract description, or share the bounds and the car-count rule from one place.

### 🟡 Maximum check runs after availability of earlier services, `src/domain/services/service-offering.ts:258-275`
**Problem**: Shape, duplicate, and breakfast-car errors are raised first, but "above the branch maximum" is evaluated in the second loop. An inactive earlier service in the list returns SERVICE_UNAVAILABLE before a later transfer's over-max field error.
**Why it matters**: Minor ordering inconsistency with the stated "field errors before SERVICE_UNAVAILABLE"; acceptable because the maximum depends on the offering, and the 1 to 10 range is checked up front.
**Suggested fix**: Document the intent in the function comment, or check the maximum for every active transfer before returning an unavailable result.

## Strengths
- Migrations are sound: the enum value is added alone, the next migration backfills (3 cars per transfer offering, 1 per transfer snapshot) before adding the CHECKs, breakfast stays null, and nothing in M8-T1's `ReservationService_values_check` conflicts. Schema enum order matches `ADD VALUE` (appended last), so there is no drift.
- The CHECKs are strict at the database: kind-specific `vehicles` and `maxVehicles`, PER_VEHICLE only on transfers, no child price, and `adultQuantity = vehicles` with `childQuantity = 0` on stored PER_VEHICLE lines.
- `validateReservationPriceSnapshot` compares stored car count with the recomputation strictly (`!==`), so a null on a transfer, a mismatch, or a count on breakfast is rejected.
- The upsert identical-write detection includes `maxVehicles`, and the audit before and after snapshots include it; the concurrency test covers the row-locked read.
- Fail closed on a transfer offering with a null maximum, and clients still cannot send prices (strict object).

## Test coverage
Good. `tests/integration/transfer-vehicles-migration.test.ts` upgrades populated storage, checks preserved prices and backfill, constraint failures (23514), and Prisma drift. `tests/unit/domain/transfer-vehicles.test.ts` covers pricing order, defaults, max, breakfast refusal, duplicates, details, pricing keys, S36 default, and fail closed. Integration tests cover P6 (indexed field errors for 0, 4, 11, 1.5, null, "2"), S35/S36 audit and identical writes, and snapshot persistence; the E2E test covers P6 end to end. Gaps: no test for whitespace-only details, and no test of the unavailable-versus-over-max ordering across two services.

## Author response

After the review, the author changed or answered each finding. The gates were rerun on the final tree: `npm run check` (1919 unit tests), the full integration suite (633 tests in 42 files), and the P6 E2E test in the `branches` project, all passing.

- **Empty details:** fixed. Blank text after trimming is stored as no details (`null`), with a unit test.
- **S36 resets the maximum:** kept as approved (S36 is a full replacement, Q-82 default 3). The contract now says so in the `maxVehicles` description, and the regenerated OpenAPI carries it.
- **Contract and domain `details` rules:** fixed. The P6 contract refuses control characters like the domain, with an HTTP test on `services.0.details`. The car count validator stays in both files on purpose: rule D-7 lets `src/contracts` import only `zod`, so it cannot share the domain schema.
- **Maximum checked after earlier services:** kept. The maximum is branch data, so this is a data dependent refusal, checked in request order like availability. Shape errors that do not depend on branch data (unknown kind, duplicates, a car count on breakfast, a count outside 1 to 10) are all reported before any offering is read.
- **Nit, hardcoded 10:** fixed. `SERVICE_MAX_VEHICLES` now lives in `service-price-unit.ts` and both files use it.
- **Nit, optional `maxVehicles` in the audit snapshot type:** kept. Audit events written before M8-T3b have no such key, and the type describes stored events of every age.

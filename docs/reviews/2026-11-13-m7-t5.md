## Resolved findings

### Resolved blocker: coupon list could return foreign branch scope during a concurrent edit

**Original location**: `src/infrastructure/db/prisma/repositories/reservations/commercial/coupon-repository.ts:116`, before the correction.

**Problem**: `findMany` applies Manager scope in the parent coupon query, but Prisma then loads `CouponBranch` in a separate statement. With the configured PostgreSQL client, these statements do not share a snapshot. An Admin can commit a scope change between them, so the returned coupon contains branches that never passed the Manager authorization predicate. This breaks spec 0004, Decision 8, and the approved requirement that Managers see only nonempty coupon scopes entirely within their assignments.

**Why it matters**: A deterministic reproduction on `rivana_test` created a coupon for `review-own-branch`, then paused the reader after its parent SELECT while an independent production `ManageCoupons.update` moved it to `review-foreign-branch`. The Manager assigned only to `review-own-branch` received that coupon with `branchIds: ["review-foreign-branch"]` and the earlier parent timestamp. The reproduction used the actual Prisma adapter and repository; it did not fabricate the repository result. Synthetic records were removed afterward.

**Suggested fix**: Load the scoped coupon and its branch IDs from one PostgreSQL statement, or use a consistent snapshot for the full read. Preserve filtering before pagination and counting. Add a deterministic regression that commits the Admin move between the original parent query and relation hydration, and verifies that no response mixes authorized parent data with foreign branches.

**Resolution verified**: `src/infrastructure/db/prisma/repositories/reservations/commercial/coupon-repository.ts:120` now selects the scoped coupon and a correlated branch ID array in one PostgreSQL statement. The item and count statements share the same parameterized predicates, including nonempty Manager scope, every assigned branch, active flag, branch filter, and literal code search. Filtering still precedes pagination. `tests/integration/reservations/coupons.test.ts:545` retains the exact interleaving; the author confirmed it fails against the original implementation, and the reviewer independently confirmed it passes against the correction. The first response contains a coherent earlier authorized state, and a subsequent Manager query excludes the moved coupon. The blocker is closed.

## Minor
### 🟡 Dynamic deep import left in a test, `tests/unit/content/catalog-commands.test.ts:311`
**Problem**: `import("@/application/content/catalog-queries")` for `contentGaps`. ESLint's no-restricted-imports normally also flags dynamic imports in tests, and the D-8 test scans `src` only, so this is invisible to the test.
**Why it matters**: Acceptable as a documented exception (internal helper, nothing outside uses it, exporting it would widen the index for a test). But it is an undocumented hole if lint does not cover tests.
**Suggested fix**: Add a one-line comment at the call site stating the intentional exception, or exercise `contentGaps` through `CatalogQueries` output (`gaps`).

### 🟡 Import scanner ignores dynamic imports and `tests/`, `tests/unit/architecture/module-boundaries.test.ts:15`
**Problem**: `importPattern` matches only static `import/export ... from`. A dynamic `import("@/application/x/internal")` in `src` would pass the D-8 test.
**Suggested fix**: Optionally extend the regex to `import\(["']...["']\)`. Low priority.

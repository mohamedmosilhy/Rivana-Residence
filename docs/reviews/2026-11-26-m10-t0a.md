## Major

### 🟠 Booking step names disappear before storage, `src/application/analytics/index.ts:71`

**Problem.** ADR 029 and spec 0007 require the collector to record booking step views. The recorder validates each name and uses it to compute the numeric funnel step. It then drops the name itself. The approved data model sketch also omits a field for it.

**Impact.** A guest advances from details to verification on the same booking page. Both rows have the same event name, path and null funnel step. A reader cannot tell which step the guest saw.

**Suggested fix.** Confirm storage with the owner. Preserve the fixed booking step name independently of the numeric funnel step. An HTTP test can submit two steps on one page and inspect both stored rows. A database check can enforce the allowed names and their relationship to the event type.

### 🟠 A strict validation error can return HTTP 500, `src/app/api/v1/_http/body.ts:95`

**Problem.** The existing error collector uses a plain object and assumes each existing property is an array. The new P11 route relies on this collector for its strict field validation contract.

**Impact.** A top level unknown field whose name matches an inherited object method makes the accumulator call an array method on a function. The shared wrapper handles the resulting exception as an internal error. P11 promises a 422 response for unknown fields.

**Suggested fix.** Use a map or a dictionary with no prototype. Exercise the inherited name through the route and check the status and field error.

### 🟠 The existing seed gate fails, `tests/integration/seed.test.ts:157`

**Problem.** The new seed step appends the Analytics entry to the production seed log. The ordered expectation still has eight entries. The repository requires the integration gate to pass for this task.

**Impact.** A successful seed of an empty database now fails its integration test. The reviewer observed nine actual entries where the test expected eight.

**Suggested fix.** Include Analytics in the ordered expectation and rerun the seed test alongside the existing assertions for empty analytics tables.

## Minor

### 🟡 Simultaneous page views leave the exit page ambiguous, `src/domain/analytics/site-session.ts:74`

**Problem.** FR-ANL defines the exit page as the last page of an incomplete session. One batch gives every row the same timestamp. The summarizer accepts no event ID and sorts on the timestamp alone.

**Impact.** Two page views from one batch can reach the summarizer in either database order. It reports a different exit page for each ordering.

**Suggested fix.** Use the stored event ID as the secondary sort key. A test can supply equal timestamps with two different IDs in reverse order and assert the later page.

### 🟡 One batch repeats catalog reads, `src/application/analytics/index.ts:60`

**Problem.** The public collection handler resolves a branch and room separately for each event. The review rubric calls for avoiding redundant database work on hot paths.

**Impact.** Twenty views of the same listing trigger forty sequential catalog reads before inserting one batch.

**Suggested fix.** Reuse lookup results within the batch, including misses. Keep room results keyed by both branch and room slug. A focused test can count calls across repeated events.

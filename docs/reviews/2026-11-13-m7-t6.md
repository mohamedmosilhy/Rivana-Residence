# Review, m7-booking-quote (M7-T6), 2026-11-13

**Reviewed by**: claude-opus-5-5, fresh context (author on a different session)
**Scope**: 32 files (22 tracked, 10 new), uncommitted vs HEAD 42130bd
**Verdict**: Changes requested

## Summary

M7-T6 adds `QuoteBooking` and public `POST /api/v1/quotes` (API-P6). The endpoint combines several units, the requested services, an optional coupon and VAT, all from server rows. It also adds the `quote` and `quote-coupon` limiters (the second one runs after the body is validated, through a new `rateLimitAfterBody` hook), two typed errors, and cleanup for every public limiter namespace. The money path is correct and reads no client value: both the contract and the domain parser are strict, and the response DTO is an allowlist. The coupon refusal shape is uniform, and the limiter order is right. The one Major finding is that the check order is not tested, although the approved task card promised it and the enumeration surface depends on it. The other findings are a missing retry on the inventory read, a heavy catalog read on a public endpoint, a per phone oracle that M8 will expose, and some weak tests.

## Verified against the contract (no finding)

- **No client money**: `quote-request.ts:34-64` and `contracts/api/v1/quotes.ts:15-50` are both `.strict()` at every level. Every amount comes from `RateBatchReader`, `ServiceOffering` rows, the `Coupon` row, or `CommercialSettings` (`quote-booking.ts:161-282`). Integration tests refuse `total`, `discount`, `vatRateBasisPoints`, a line `price`, and six lines (`quotes.test.ts:473-506`).
- **Order of checks vs Decision 10**: the code follows structural parse, branch (404), public stay policy, listing, occupancy, availability and price, services, coupon, then VAT. The branch is resolved before `validatePublicStay`. That is unavoidable, because "today" needs the branch time zone, and it is the same order P5 uses.
- **Grouping**: repeated listings are grouped by `room.id`, with quantity equal to the line count (`quote-booking.ts:151-199`). A short group, a blocked night, an unpriced night, or zero units marks every index of that group unavailable. Indexes line up with the request because any line refusal returns early (`:145-148`).
- **`bookable`**: it is `onlineBookingEnabled` when the quote is available and `false` otherwise (`:206`, `:289`).
- **Coupon refusals**: one constant message, plus `fieldErrors.couponCode` (`result.ts:102-113`). A malformed code is `NOT_FOUND` and never reaches the store (`:234`). The redemption count is skipped only when the code is unknown, and the reason already discloses that by spec (AC-4), so the skip leaks nothing new.
- **Limiters**: `quote` runs before the body is parsed, and `quote-coupon` runs only after contract validation (`routes.ts:242-263`). An invalid body does not consume the coupon limit (`http-layer.test.ts:513-520`). Keys come from the HMAC of the client address only (`quotes.test.ts:622-630`). The phone is never logged: the logger is an allowlist and bodies are not logged.
- **Cleanup prefix**: `LIKE 'rl:quote:%'` cannot match `rl:quote-coupon:…` (the character after `quote` is `-`, not `:`). No limiter name contains `_` or `%`. The integration test covers `rl:quote-extra:old` (`quotes.test.ts:632-656`).
- **Problem mapping**: `COUPON_INVALID` returns 422 and `SERVICE_UNAVAILABLE` returns 409 (`problem.ts:37-41`), both pinned in the http-layer table.
- **No internal ids** in the response: `_dto/quotes.ts` is an explicit allowlist (`branchId`, room ids, and period ids are dropped). The e2e test asserts this with a regex.

## Major

### 🟠 The check order (Decision 10) is not tested, though the task card promised it, `src/application/quotes/quote-booking.ts:200-249`
**Problem**: Each refusal is tested on its own. No test pins which one wins when several apply. Three cases are untested: (a) an unavailable line plus a bad coupon must return `200 available:false` and must not call `coupons.findByCode`; (b) an unavailable service plus a bad coupon must return 409, not 422; (c) a refused service must not call the coupon store or the redemption port. Task card item 13 lists "check order" as a unit test, and that test is absent.
**Why it matters**: The order is security relevant here. Availability and service checks act as gates before the coupon oracle, so a guesser needs a valid, available stay. A later refactor (for example M8 reusing `QuoteBooking`) could move the coupon block earlier and change the enumeration surface and the status codes without any test failing. The risk tier is CRITICAL.
**Suggested fix**: Add unit cases that combine refusals and assert both the result code and that `findByCode` and `count` were not called. Optionally add one integration case: sold out plus `couponCode: "NOPE"` returns 200.

## Minor

### 🟡 The inventory read skips the `readListingNights` retry, so a concurrent CMS edit returns a misleading 404, `src/application/quotes/quote-booking.ts:161-169`
**Problem**: `rooms.listPublished` and `inventory.readNights` are separate reads. If a listing is deleted or unpublished between them, `PrismaInventoryReader` returns `NOT_FOUND`, "The requested listing was not found." (`inventory-reader.ts:96`). `QuoteBooking` passes that through as a 404. P5 wraps the same pair in `readListingNights`, which re-lists once for exactly this race, and the task card said to reuse it. No test covers a failed `readNights`.
**Why it matters**: A guest sees a 404 for an existing branch instead of the 422 `lines.N.roomSlug` field error. The endpoint's 404 then means two different things.
**Suggested fix**: On `NOT_FOUND` from `readNights`, re-list once and re-resolve the slugs, as `readListingNights` does. Alternatively, map it to the line field error. Add a unit test with a reader that returns `NOT_FOUND`.

### 🟡 A public endpoint loads the full room graph for every listing in the branch, `src/application/quotes/quote-booking.ts:119-125` / `src/composition/commercial.ts:78`
**Problem**: `RoomRepository.listPublished` includes `roomGraph` (features, plus media with their `media` join) for every published listing of the branch. The quote only needs id, slug, name, accommodation type and occupancy limits. The card said to reuse the M6 `AvailabilityCatalog` that `SearchAvailability` uses.
**Why it matters**: Each request at up to 60 per minute per client (or the shared anonymous bucket) runs three extra joins and hydrates images that are thrown away. That is avoidable load on the hottest public write-free path.
**Suggested fix**: Use `AvailabilityCatalog.listRoomTypes(branchId, "PUBLISHED")`, or add a slim port that selects only the needed columns, and narrow the `rooms` port type to match.

### 🟡 An unverified `phone` with a `PHONE_LIMIT_REACHED` reason becomes a per guest oracle once M8 swaps the reader, `src/application/quotes/quote-booking.ts:236-249`, `src/contracts/api/v1/quotes.ts:40-46`
**Problem**: P6 accepts any string as `phone` and returns `context.reason: "PHONE_LIMIT_REACHED"`. That is harmless today only because `EmptyCouponRedemptionReader` returns zeros. When M8 adds persisted redemptions, anyone could ask whether phone X has already used code Y, which breaks AC-4 ("never reveals … other guests' use"). The spec notes that M8 re-validates at booking, but P6 itself would still answer the probe.
**Why it matters**: It is a latent privacy leak in a public contract that is being frozen now.
**Suggested fix**: Record an explicit M8 obligation now: P6 must either ignore `phone` until it carries a verified token, or fold `PHONE_LIMIT_REACHED` into the generic reason on the public route. Add a unit test or a code comment that pins this, so the M8 reader swap cannot ship without the change.

### 🟡 The "reads only" unit test only checks its own fakes, `tests/unit/application/quote-booking.test.ts:337-344`
**Problem**: It asserts that the method names on the test's own fake objects start with `find|list|read|count`. It can never fail because of production code. The real composition passes full repositories that do have write methods (narrowed only by `Pick`).
**Why it matters**: It gives false assurance for the task acceptance criterion "a refused request writes nothing". The integration snapshot test (`quotes.test.ts:508-522`) is the real evidence, and it covers only a successful request.
**Suggested fix**: Drop the test, or replace it with a type-level check on `QuoteBookingReaders` keys. Extend the integration snapshot to cover a refused request too (coupon refusal and 409).

### 🟡 One client can block coupon quotes for everyone when proxy headers are not trusted, `src/application/shared/public-rate-limit-policy.ts:17-21`
**Problem**: Without a trusted client address, every request shares one anonymous bucket (deployment.md:90). For `quote-coupon` that means 20 coupon attempts per 10 minutes for the whole site, so a single script can deny coupon quotes to every guest for 10 minute periods. P5 has the same mechanism, but its limit is 60 per minute.
**Why it matters**: It is an operational DoS on a revenue feature if `AUTH_TRUST_PROXY_HEADERS` is misconfigured.
**Suggested fix**: In the deferred deployment and security doc sync, list "trusted proxy rehearsed" as a precondition for exposing P6 coupons. Consider logging or alerting when the anonymous bucket is in use.

### 🟡 Cleanup now deletes up to 3,000 rows per call, but tests and docs still say 1,000, `src/infrastructure/db/prisma/repositories/public-rate-limit-store.ts:51-61`
**Problem**: The limit now applies per namespace across three namespaces. `tests/integration/public-rate-limit.test.ts:183` ("deletes at most 1,000 rows per invocation") still passes only because it seeds a single namespace. Its sibling test name, "deletes only expired availability buckets", is also stale. Stale docs: `docs/operations/deployment.md:80`, `docs/security/security-controls.md:26`, `src/app/api/AGENTS.md:15` (all part of the deferred doc sync).
**Why it matters**: The new port comment correctly says "per namespace", but the test names now state a guarantee the code no longer has.
**Suggested fix**: Rename the two tests. Add one case that seeds more than 1,000 rows in two namespaces and asserts the per namespace cap. Update the three docs in the sync.

## Strengths

- `rateLimitAfterBody` is a small, well placed extension. It runs after validation and takes the same 429 and `Retry-After` path. Unit tests cover null, both limits, a denial from the second limit, and the case where an invalid body does not consume the second limit.
- `findByCode` reads the coupon and its branch ids in one SQL statement through the `upper(code)` index. This avoids the split-read disclosure that the M7-T5 notes warn about.
- The coupon refusal is one constructor with one message constant, and `context.reason` is typed to `CouponRefusal`.
- Integration tests run the real route handler against PostgreSQL to the cent for worked examples 1 to 5, VAT 0 and 10000, and blocked and unpriced lines. They also check limiter keys for PII and the cleanup namespace boundaries.

## Test coverage

Covered: worked examples (integration 1 to 5, unit 2 to 5), strict bodies, grouping, unpriced listings, blocked units, `bookable`, 404 for unknown and inactive branches, a foreign listing as a 422, occupancy and stay refusals, services (requested only, missing and inactive 409, duplicate 422), all seven coupon reasons in unit tests and five in integration (the limit reasons cannot trip with the zero adapter, as the spec says), case and space matching, malformed codes, both limiters with `Retry-After` and recovery, parallel admission, PII-free keys, cleanup namespaces, and the http-layer code table.

Gaps: the check order and precedence (Major above), a failed `readNights` and the CMS race, a "writes nothing" check on a refused request, and the cap per namespace in cleanup.

## Author resolution (2026-11-13)
- Major, order of checks untested: fixed. New unit tests prove an unavailable line wins over a bad coupon (no service, coupon, redemption, or VAT read), an unavailable service wins over a bad coupon (no coupon or redemption read), and a bad coupon is refused before the VAT read.
- Minor, no retry on a vanished listing: fixed. `QuoteBooking` re-reads the catalog once on `NOT_FOUND` from the night read, so the vanished listing becomes the usual 422 `lines.N.roomSlug`; a second failure is reported as is. Both paths tested.
- Minor, vacuous "reads only" test: removed. The integration "writes nothing" test now also covers a refused coupon, an unavailable service, and an unavailable line.
- Minor, cleanup test name and bound: renamed to "per namespace" and a new integration test proves a full `quote` namespace cannot starve `availability` (1,004 rows in one run, then the rest).
- Nits fixed: the e2e comment, and an over long coupon code is now a normal `COUPON_INVALID` `NOT_FOUND` (no length limit in the contract or the domain parser; the body size cap bounds it), with a unit test.
- Left open on purpose, for the owner:
  - Heavier `listPublished` read: the lighter `AvailabilityCatalog` has no slug or accommodation type, so using it needs a port change. Accepted as is for M7; a later task can add a slim public listing reader.
  - Phone enumeration: an unverified `phone` plus the `PHONE_LIMIT_REACHED` reason would let anyone probe which phone used which coupon once M8 persists redemptions. Obligation for M8: only honour `phone` from a verified source (phone verification token) or stop returning that reason publicly. To be written into the M8 brief and spec 0004 in the docs sync.
  - One shared bucket when proxy headers are not trusted (anonymous fallback): documented in the deployment and security docs sync.
  - Nits not changed: the `kind` cast in the DTO, test names that claim slightly more than they check, worked example 1 is covered by the integration test but not the unit test.
- Stale doc statements: reconciled in the Stage 7 docs sync after acceptance.

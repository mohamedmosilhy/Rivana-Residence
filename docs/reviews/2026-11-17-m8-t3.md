## Major

### 🟠 Coupon snapshot persistence branches have no regression coverage, `src/infrastructure/db/prisma/repositories/reservations/reservation-repository.ts:183`

**Status**: Resolved. The cases at `tests/integration/reservations/reservation-repository.test.ts:295` now exercise both kinds through real PostgreSQL, check raw stored kind and value, distinguish the fixed value of 500 from its capped discount of 200, assert the financial totals, and reread the unchanged snapshot after editing and disabling the live coupon.

**Problem**: The new write path converts a percent coupon to basis points and a fixed coupon to cents. The read path reconstructs those distinct types at lines 66 to 77. Every repository fixture currently uses `couponValue: null`, so neither populated branch is exercised. The existing P6 coupon tests only compute quotes and do not pass their snapshots through this repository.

**Why it matters**: Preserving the monetary snapshot is part of the approved T3 responsibility. A percent coupon stored as an amount, or a fixed coupon whose original value is replaced with its capped discount, could pass every current storage test and corrupt the information later used for a stay change. The review rubric classifies uncovered branching logic as Major, and this is money persistence.

**Suggested fix**: Add real PostgreSQL round trips for both coupon kinds, including coupon id and code, the stored kind and value, discount, taxable amount, VAT and total. Include a fixed coupon above the subtotal, so its original value differs from the applied discount, and assert that the stored value remains unchanged. A read after changing the live coupon or VAT settings can also establish that the repository returns the historical snapshot. This needs no coupon redemption workflow or new production port.

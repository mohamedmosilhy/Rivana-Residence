## Summary

The outbox claim, lease, fenced completion, retry schedule, payload scrubbing, and token cleanup match the approved Decision 5 mapping. No actionable findings.

## Strengths

- Claim is one row per short transaction with `FOR UPDATE SKIP LOCKED`; the provider is called outside any transaction (`dispatch-outbox.ts:51-61`, `outbox.ts:47-78`).
- Completion is fenced on `attempts` and `PENDING`, so a late worker cannot overwrite a re-claimed row (`outbox.ts:79-92`). Terminal updates clear the payload, so manage links do not outlive delivery.
- An expired final lease ends `FAILED` as `DELIVERY_UNCONFIRMED` instead of exceeding the attempt budget (`outbox.ts:54-66`).
- `lastError` is a fixed class plus a bounded numeric code, never provider text (`dispatch-outbox.ts:94-119`).
- Email output is HTML escaped, subject sanitised, and the Message-ID is stable per row for SMTP dedupe (`reservation-email.ts`).
- Token expiry clears hashes only and leaves `updatedAt`, version, and history untouched (`outbox.ts:95-110`).

## Notes (not blocking)

- A crash after provider acceptance can duplicate a delivery (at least once); documented in the migrations doc and spec.
- A staff alert with no branch email is queued with an empty recipient so it fails visibly (`INVALID_MESSAGE`); intended.

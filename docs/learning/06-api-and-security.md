# 6. API and security

## Ground rules (`/api/v1`; public at top level, staff under `/api/v1/staff`)
JSON only, camelCase, 32 KB body cap; dates `YYYY-MM-DD`; money `{amountMinor, currency}`; unknown fields rejected (`.strict()`); DTOs only (never Prisma/domain objects); pagination `?page&pageSize` (max 100); responses `no-store` except public catalog GETs (availability never cached); additive changes stay v1.

## Status codes
401 not signed in; 403 lacking capability; **404 not found or in an inaccessible branch** (no existence leak); 409 business conflict; 412 stale version; 422 invalid values with `fieldErrors`; 429/503 with `Retry-After`.

## Errors: RFC 9457 problem+json
`type, title, status, code (stable machine value), detail, requestId, fieldErrors?, context?`. Use cases return `Result` with a code; one table in `_http/problem.ts` maps code -> status. Unexpected errors -> `500 INTERNAL` with request id only. ~30 reservation codes planned (`PRICE_CHANGED`, `COUPON_INVALID`, `PHONE_BLOCKED`, `CANCELLATION_WINDOW_CLOSED`, ...).

## Endpoints
Implemented: `GET /health`, P1-P4 (branches, listings), A1-A3 (staff branches list/create/patch).
Planned: P5 availability, P6 quote, **P7 create reservation**, P8 Paymob callback, P9/P10 WhatsApp code; G1-G4 guest; S1-S19 staff reservations; S20-S29 inventory/blocks/sync; S30-S39, S44/45 pricing, services, coupons, payments; S50-S54 guests; S40-S43 reports/audit; S60-S62 broadcasts; A4-A8 admin settings. The table in `docs/api/api-contracts.md` lists capability, transaction/lock/idempotency/audit and errors per endpoint: it is the review checklist per task.

## OpenAPI
`docs/api/openapi.json` generated by `npm run openapi` from Zod contracts + route registry; a unit test fails if the committed file differs.

## Authentication
- Public: none; rate-limited by HMAC of client address (no raw IP stored).
- Guest: `Authorization: Bearer <manage token>`, token hash only stored.
- Staff: Better Auth session cookie (`HttpOnly`, `SameSite=Lax`, `Secure` in prod), `rivana-staff.session_token`, path `/` (covers `/admin` and `/api/v1/staff`); DB session and branch assignments checked per request.
- Paymob: `webhookRoute`, HMAC over raw body, no session/CSRF.
- CSRF for cookie writes: `Origin == APP_URL`, `Sec-Fetch-Site: same-origin`, JSON content type (forces a preflight the API never grants). No CORS at all.

## Security controls
Closed staff accounts, >=12-char passwords, scrypt, login throttling; authorization in use cases (proxy redirect is convenience); Zod on all input; rich text as structured tree; Google-only map embed allowlist; uploads: quarantine, magic bytes, random keys, no SVG, size limits, traversal checks; contact form honeypot + rate limit; branch slug always resolved server-side; `new-cairo` cannot be deactivated; CSP/headers in `infrastructure/http/security-headers.ts`; logs never contain bodies/tokens/cookies/PII.

Risks to re-check per task: phone-verification abuse, guest-token leakage, webhook forgery, cross-branch access, coupon guessing.

## Remember
Strict JSON, one error shape, stable `code`. Authentication in the wrapper; authorization and rules in the use case. Only branch endpoints exist now.

Read: `docs/api/api-contracts.md`.
